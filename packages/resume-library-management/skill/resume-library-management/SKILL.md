# 简历库与简历管理

## 目标

把简历从一次性文档改造成可追溯的职业事实系统。先建立来源与事实，再建立模块、岗位画像和输出；不得为了某个岗位在事实层创造经历。

## 五层结构

1. 来源层：登记来源编号、材料类型、证据等级、核验状态、日期和定位信息。
2. 事实层：保存教育、任职、项目、案件、证书和能力事实，并引用来源。
3. 模块层：引用事实编号形成可复用表达，明确本人贡献和团队边界。
4. 岗位层：解析岗位目标、必需能力、加分项、风险和模块选择规则。
5. 输出层：为一个明确目标生成独立版本，列出使用的事实与模块并标记人工审阅状态。

## 必须遵守

- 新材料先登记来源，再提取候选事实。
- `证据等级`、`核验状态`和`输出审阅状态`是三个不同字段。
- 同一文件的不同格式不自动视为多个独立来源。
- 案件必须分开记录`客观事实`、`本人动作`和`团队或外部贡献边界`。
- 模块只能引用事实，不能反向覆盖事实层。
- 冲突不得静默删除；保留冲突说明，确认后更新当前事实。
- 每个目标输出使用独立编号、岗位画像、模块清单和事实快照日期。
- 未经人工审阅的输出只能标记为待审阅草稿。

## 工作流

### 1. 登记来源

为材料分配`SRC-`编号，记录标题、类型、证据等级、核验状态、日期、逻辑位置和可用范围。原件路径使用逻辑根或相对路径，不在可分享输出中写绝对路径。

### 2. 提取与核验事实

为经历、项目、案件和资格建立稳定编号。保存材料明确支持的事实、来源编号、核验状态、冲突和最后复核日期。AI推断只能进入待核说明。

### 3. 建立模块

模块引用一个或多个事实编号，保存简版表述、标准表述、能力标签、适用岗位、本人贡献边界和输出就绪状态。

### 4. 解析岗位画像

从岗位描述提取核心任务、必须条件、优先条件、风险、关键词和证明要求。没有真实岗位描述时，明确标记为通用画像。

### 5. 生成多目标输出

为每个目标选择必要模块，控制重复和篇幅。输出附带事实与模块引用、未决问题、保密提示和人工审阅状态，不自动投递。

### 6. 回写规则

输出阶段发现事实错误时，回到事实层修订并重新生成模块和输出。不得只在简历文案里修补事实。

## 校验

可选运行：

```powershell
python scripts/validate_library.py --library examples/synthetic-library.json
```

校验只覆盖结构、引用、贡献边界和部分隐私形态。真实性、保密义务和对外表达仍需人工判断。
