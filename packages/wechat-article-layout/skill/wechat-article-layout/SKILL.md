# 微信公众号半自动排版

## 适用时机

当用户已经冻结文章 Markdown 和正式图片，需要生成可核验的公众号人工粘贴交付物时使用。

## 强制边界

1. 先确认正文已经冻结，图片已经获准进入本轮构建。
2. 不修改文章事实、标题或图片；输入不一致时停止并报告。
3. 不请求或保存公众号凭据，不调用公众号 API，不创建草稿、排期或发布。
4. 构建成功只能报告“本地产物就绪”，不得报告“公众号页面完成”。
5. 真实交付必须经过复制到公众号编辑器、保存重开和手机人工预览。

## 工作流

1. 用 `assets/handoff-checklist.template.json` 建立交接清单。
2. 运行 `scripts/build_layout.py --validate-only` 核对冻结状态、图片引用与支持结构。
3. 正式构建到一个新的输出目录。
4. 打开 `preview.html` 做桌面和窄屏预览。
5. 核对 `validation-report.json` 与 `build-receipt.json` 的输入、输出 SHA-256。
6. 人工把 `copyable.html` 正文复制到公众号编辑器。
7. 保存重开并在手机预览中检查标题、段距、图片节奏、重点和文末。
8. 只有人工验收后，才把交接清单中的 `mobile_acceptance` 记为 `passed` 并重新构建回执。

## 失败处理

- 图片缺失、清单不一致、正文未冻结、远程图片或不支持结构：修复输入后重建。
- 本地预览通过、公众号预览失败：保留失败截图或差异记录，只调整公开样式配置或输入，不让构建器改写正文。
- 单图错误：只替换对应图片并验证新哈希，不重做其他已经确认的素材。
