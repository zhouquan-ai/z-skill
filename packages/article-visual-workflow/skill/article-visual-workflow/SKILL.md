# 文章视觉规划与生图

先决定图片要帮助读者理解什么，再决定怎样生成。

## 输入闸门

开始前确认：

- 文章内容已经冻结，或用户明确接受当前版本用于规划；
- 能够读取完整正文和标题层级；
- 已知公开、隐私、保密和素材权限边界；
- 本阶段是只做规划，还是已经授权生成具体图片；
- 真实人物、案件、单位和未公开内容是否允许进入所选图像工具。

正文未冻结时，只指出缺口，不建立伪精确插入位置。权限不清时使用仿真或抽象方案，不把敏感内容送入模型。

## 第一阶段：视觉故事简报

用不超过 200 字回答：

1. 文章解决的现实问题；
2. 主要人物或对象；
3. 触发事件、核心行动和前后变化；
4. 最值得视觉化的冲突或关系；
5. 哪些内容没有独立图片价值；
6. 需要避免的隐私、版权、刻板印象和事实误导。

简报不是文章摘要。图片必须承担理解、记忆、节奏或关系说明中的至少一项任务。

## 第二阶段：逐处路由

每个候选位置只能选择一种结果：

- `场景图`：去掉文字后，人物、对象、动作和环境仍能表达一个具体事件；
- `示意图`：需要精确节点、箭头、分类、对比、层级或逐字标签；
- `不配图`：图片只会重复正文、制造装饰或引入不必要风险。

不得按章节数量凑图。相邻场景图应改变人物数量、动作、空间、机位或景别，避免模板化重复。

## 第三阶段：冻结图片计划

复制 `assets/image-plan-template.md`，为每个候选位置记录：

- 决策及理由；
- 正文中的逐字插入锚点；
- 图片承担的唯一任务；
- 场景图的主体、动作、环境、镜头、风格和禁止元素；
- 示意图的节点、箭头、阅读顺序和 ASCII 草图；
- 不配图位置的停止理由；
- 生成提示、验收条件和局部重做条件。

插入锚点必须逐字存在于正文。标题只能用于章节定位，不能代替正文锚点。

## 第四阶段：生成提示

场景图提示只包含当前图片需要的信息：

- 一张图、一个事件、一个独立文件；
- 主体、动作、空间、前中后景和镜头；
- 本篇确认的视觉语言、色彩和光线；
- 必须出现的主题锚点；
- 必须避免的文字、Logo、水印、拼贴、分屏和模板化元素。

不要把项目规则、JSON、文件清单、其他图片计划或失败候选塞入提示。需要准确文字、箭头和关系时改走示意图。

## 第五阶段：逐图验收

每张图生成后单独检查：

1. 文件存在、可打开，尺寸和比例符合计划；
2. 画面确实执行当前唯一任务；
3. 没有错误文字、Logo、水印、多场景拼接或明显结构异常；
4. 人物、环境和动作没有泄露或歪曲事实；
5. 与相邻图片协调但不机械重复；
6. 实际向用户展示，并区分候选、通过和淘汰。

自动检查不能代替人工视觉判断。用户未确认前，不得称为正式图片。

## 局部重做

用户只点名一张图时：

1. 冻结其他已接受图片；
2. 只记录当前图失败原因；
3. 丢弃当前失败提示中的污染元素；
4. 保留仍然有效的任务、风格和事实锚点；
5. 只重做当前图；
6. 重新展示当前有效整组，不暗中替换其他文件。

同类严重问题连续出现时停止，报告限制，不用更多随机候选掩盖方向错误。

## 结构校验

完成计划后运行：

```text
python scripts/validate_plan.py --article <冻结文章.md> --plan <图片计划.md>
```

脚本通过只证明字段、路由和正文锚点存在；不证明审美、版权、隐私或真实用户确认已经通过。
